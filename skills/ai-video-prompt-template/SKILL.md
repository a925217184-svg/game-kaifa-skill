# AI 视频分镜提示词模板

## 目的

按固定三层骨架为任意题材的 AI 视频生成专业提示词：全局风格层锁一致性、分镜层锁节奏与运镜、负面词层锁崩坏。模板不含固定风格，风格与内容由每次的设定卡决定。**每层只许有一处描述，禁止跨层重复**（实测被点名过：「写这么多的负面提示词，这么细碎，只会分散 AI 的权重」「禁止重复描述」）：凡在每镜重复的状态——**持械、群称、服装、武器、站位默认、机位默认**——一律上提到全局风格层一次性说清，让每镜专心写动作和对白；同样的原则适用于全局层：不要在全局层塞满逐条特效规格，把规格挪到第一次用到该特效的那一镜；骨架不是堆料的容器，是分层提纯的筛子。

## 使用时机

当用户请求以下任一情况时加载本技能：

- 撰写/生成 AI 视频提示词、分镜脚本
- 提到"运镜""分镜""镜头脚本""负面提示词"
- 提到具体工具（即梦、可灵、Vidu、Runway、Veo、Sora）的提示词需求
- 用户提供一段视频脚本/小说片段，希望转成 AI 视频提示词
- 剧本或需求里含**打斗 / 战斗 / 对决 / 交手 / 搏杀 / 追杀 / 混战 / 群战 / BOSS 战 / 妖兽战**等动作场面
- 用户对已有提示词的反馈是「炫酷打斗 / 不够炸 / 强化打击感 / 打的不疼 / 没手感 / 丰富特效 / 动作不流畅 / 力量感不足 / 节奏拖沓 / 环境太干净」

## 工作流程

1. **读取模板**：完整阅读 `references/template.md`，掌握三层层级、四段式画面口诀、运镜类型库与 checklist。
2. **收集设定卡**：向用户确认或从其描述中提取设定卡八项——主体角色、对手/障碍、场景、光效/特效体系、风格基调（只选一种）、总时长/镜头数、节奏基调、可选台词。缺失项做合理假设并标注，一次提问不宜超过 3 个问题。
3. **填写统一 Style**：按模板 10 个槽位（画质/渲染材质/光影/色调/动态元素/特效体系/构图/环境动态/一致性/节奏）展开成一段，槽位间不得风格矛盾；与题材无关的槽位可删。
4. **编写分镜**：按所选题材套用节奏公式（动作战斗片/叙事氛围片/产品展示片），每镜三件套：精确连续时间码 + 不重复的运镜 + 四段式画面（谁在动→怎么动→交互命中→反馈与细节）。时间码按每镜 1~1.5s（快节奏）或 3~5s（叙事）换算。
   - ⚠️ **"画面太细碎"与"渲染 BUG 多"是两个相反的信号，别弄反**（实测两轮都踩过：先是「画面太细碎、给 AI 多点发挥空间」→ 压到 41 字；下一轮用户回来说「分镜写详细一点，现在渲染出来很多 BUG」→ 必须补回四段式细版，平均 203 字／镜）。
     - **收到"渲染出很多 BUG / 崩坏 / 变形"类反馈时，不要只加负面词**——第一优先级是把**物理细节补回镜头层**：接触点（剑锋陷进铠甲、锤面与盾面撞击处）、受力方向与位移（手臂被压得下沉半寸、向后退半步）、形变（甲片向内凹陷并崩飞两片），以及反馈细节（火星／碎屑／灰尘／血雾／衣摆／气浪／光斑）。模型缺物理锚点就会自己乱补，那正是 BUG 的来源。
     - **同时把运镜的「落幅」补回来**：`景别 ＋ 运动 ＋ 落幅` 是跨镜衔接的锚；只写"景别＋运动"时，下一镜容易接不上（机位或朝向跳变）。仍不写画面占比与机位距离角度。
     - **负面词另加一组"防穿模／防跳帧"**：角色互相穿模、武器与手分离或悬空、武器凭空出现第二把或中途消失、同一角色在同一镜内出现两次、比例与身高突变、动作瞬移跳帧、脚不落地滑行、道具还没接触就产生反应、影子方向与光源矛盾、盔甲与布料黏连融化、手指数量与关节异常。
     - ⚠️ **NEG 按层分流，绝不跨层重复（这条比 NEG 瘦身更优先）：
- 整体设定层：只放摄影机硬件参数（传感器/帧率/镜头型号/焦段/光圈/画幅/材质/色彩基调）＋风格速记（角色服装持械、主角色、节奏基调、特效清单）。绝不写机位/视角/视线落幅/演员朝向这些具体摄像机运动——这些是分镜层的事。
- 逐镜正文层：每镜开头的简述（中景横移跟拍/过肩迎面反打/特写俯拍）就是机位层，机位逻辑（背对镜头/越肩反打/视线方向/落幅落点）只在这里逐镜写死，不在设定和 NEG 里总结。
- NEG 层：纯负面兜底（画风跑偏/肢体畸形/穿模与武器分离/多余人物/字幕水印），完全不出现机位相关的禁项（不要写"不要转头看镜头""不要站到人物与怪物之间"——这些应当用正描述补而不是用负词禁）。
理由：三层各管一头。机位规则一旦放进设定层或 NEG 层，必然与分镜层每镜的"背对镜头""越肩反打"重复，权重被稀释。
5. **打斗场景检测（命中即强制走手册，不命中不加载）**：用下面一节的触发词扫一遍剧本/需求（含用户给的脚本截图里的画面）。命中任一条件 → 整篇读 `references/combat-handbook.md`，按手册的七字段备料、打击感五件套、环境破坏四段式写打斗镜；不命中 → 直接跳到第 6 步，不要无脑加载手册。
- 默认输出完整三层结构；用户使用单镜工具（5-10s）时跳过分镜层，压缩为一段。
- 逐镜生成工具（可灵/Runway/即梦单镜）：提醒用户每镜提示词 = Style + 该镜内容 + 负面词，用上一镜尾帧做下一镜图生视频参考。
- **交付双文件，不要只给 .md**：`01_分镜提示词_<片名>.md`（设定卡／声线锁／逐镜／负面词／时长核算／待确认项，给人核对）＋ `02_提示词_可复制版.txt`（块 A STYLE／块 B NEG／块 C VOICE／块 D DIALOGUE ＋ 逐段纯文本）。**用户明确反馈过 .md 在预览面板里选不中、复制不了**，所以凡是"要拿去粘贴生成"的内容一律放 `.txt`，`.md` 只承担阅读与核对。

## 打斗 / 动作场景：自动检测 + 强制走手册【2026-10-14】

**命中下面任一条件 = 进入「打斗模式」：必须整篇读 `references/combat-handbook.md`，按它的规范落笔，不许凭感觉写。**

**① 场面词（剧本/需求里出现即命中）**：打斗 / 战斗 / 对决 / 交手 / 搏杀 / 肉搏 / 格斗 / 厮杀 / 追杀 / 混战 / 群战 / BOSS 战 / 妖兽战 / 比武 / 决斗 / 兵器相撞 / 挥剑 / 斩击 / 拳脚 / 连招 / 受击 / 终极招式 / 反击 / 突袭 / 攻防。

**② 需求词（用户反馈里出现即命中）**：炫酷打斗 / 不够炸 / 场面不够大 / 强化打击感 / 打的不疼 / 没手感 / 丰富特效 / 特效单调 / 动作不流畅 / 卡断 / 一块块的 / 力量感不足 / 不出力 / 一拳就赢太轻松 / 节奏拖沓 / 环境太干净 / 看不清谁打了谁 / 想要第一人称 / 想要悬念收尾。

**③ 画面判据（用户给的脚本截图或文字里出现）**：任何「A 打中 B」的交互镜头都算——撞飞 / 击退 / 贯穿 / 塌陷 / 火花 / 冲击波 / 血雾 / 碎裂，哪怕全篇只有一镜。

**进入打斗模式后四步**

1. **读**：整篇读 `references/combat-handbook.md`（45KB，可直接整篇读；也可按 §0.5 锚点表 Grep 定位）。**想让检测自动化时**，先跑 `python scripts/detect_combat.py <脚本文件>`（脚本在本技能 `scripts/` 下；本机另有 `F:\AI视频制作\outputs\_tools\detect_combat.py`，两者同版）——它会判定是否进入打斗模式、列出命中词与行号，并逐镜报「缺哪件打击反馈／缺触点标记／开头没写站位／一镜两事件」，按报告补即可（脚本不存在就按上面三类触发词手扫）。
2. **备料**：每镜按手册 §1.3 七字段备料——`开局站位状态 → 镜头 → 动作 → 台词 → 情绪 → 特效 → 声音`。**七字段只用于备料与自检**，落到分镜层时 `画面：` 写成一整段四段式，**不许出现 `镜头：… 动作：… 特效：` 这种并列冒号字段体**（模板固定的 `运镜：`/`画面：` 两行不算）。
3. **落位**：按手册 §1.3 ① 的落位表把七字段分别塞进设定卡 / 统一 Style / 分镜层 / 统一 NEG。
4. **自检**：逐镜查这四项，缺一项补一项——
   - **打击感五件套**（§2.3 必看）：接触闪 / 形变 / 位移 follow-through / 反作用力 / 二次破坏，并配一个触点标记词（黑白闪 / 顿帧 / 音爆 / 震屏）；
   - **环境破坏四段式**（§2.4）：设定卡【场景】项先预声明可破坏性 → 交手产生破坏 → 下一镜「画面：」开头一句继承破坏痕迹 → 环境持续运动不停帧；
   - 每镜「画面：」开头写清**开局站位状态**（谁在哪、上一镜结果），防角色位置跨镜漂移；
   - 一镜只许一个事件（掷出与命中必须拆成两镜）。

**用户提需求词时**：按手册 **§5.1 需求词 → 模块映射表**取对应模块，**只改对应句子，不重写全篇**；画面出问题按 §5.2 症状表查根因；字数吃紧按 §5.3 取舍优先级从后往前砍（最先保站位与时长，最后才砍风格形容词）。

**打斗题材必须追加的 NEG 组**（叠在第三层里，不替代原有组）：
```
打击落空无反馈、命中不产生形变与位移、被打者原地不动、力量溢出到环境但环境无破坏、
破坏一次性（下一镜环境恢复原状）、角色位置跨镜漂移、武器与手分离或悬空、动作瞬移跳帧、
违背重力的悬停、同一镜内出现第二机位切换、多余肢体与关节反折、慢镜段人物五官崩坏
```

**分工边界**：手册管「打斗内部的反馈 / 破坏 / 力量 / 代价」，模板管「三层骨架与四段式画面口诀」。两者冲突时，**打斗镜的反馈与破坏写法以手册为准，其余一律以模板为准**；本技能的输出格式永远只有三层骨架这一种，不因手册改变。

## 输入是分镜脚本截图时（高频场景，务必照做）

用户直接把剧情脚本/分镜表**截图**丢过来时，不要只读一遍就动笔——截图通常只有 1000~1300px 宽，中文小字必错。

1. **先切图放大再核对**：用 PIL 分区裁切并放大（LANCZOS），逐块读图核对台词、音效、标题行。
   - ⚠️ **关键技巧：整幅放大是无效的**。读图端会把长边压到约 1568px，源图若本就有 1000~1200px 宽，整幅放大等于白做。**只有把裁切宽度缩短，倍率才真正上去**——正确做法是**双列切分（左 0~56%、右 44~100%，带重叠）× 按带切分（每图 4 带）**，再放大到 1550px 宽，实际倍率约 2.5x。
   - 存疑的单字（如「撞/揍」「规制/管控」）再做**单字级 7 倍放大**定点确认，不要靠上下文猜。
   - Windows 上 Python 写 `/tmp/x` 会落到**当前盘符根目录**（如 `H:\tmp\x`），不是系统临时目录。
2. **角色设定图要转写成文字写进设定卡**：把三视图里的可验证特征（头盔颜色与形状、披风、掌中光球、头冠与宝石、面罩、麻袋与灯）逐条落到「外形关键特征」列，这几件标志物就是全片的防崩坏锁。
3. **必做冲突核查**：脚本描述与设定图经常打架（例：脚本写「一身基础白装」，设定图是「赤红重甲」）。**默认以设定图正稿为准**，并把冲突列入「待确认项」，绝不两边都写进分镜。
   - ⚠️ **三视图陷阱：同一件装备会被误读成多件**。角色设定图常是「人脸特写 + 3 个视角全身」，**同一把武器在 3 个视角里出现在不同的手／不同的画面侧**，很容易被写成「双持两把」。复核口诀：**先数"这角色有几只手能拿武器"，再数武器数量**——一只手拿的刀，无论 3 个视角怎么摆，都只有一把。这条踩过一次（狂战被写成"双持两把金色弯月巨刃"，实际是单手一把屠龙宝刀）。
   - ⚠️ **颜色与材质别按"差不多"写**：本次实测错在把「墨绿金渐变紧身软甲」写成「墨绿金属板甲」、把「骨白色石质肩甲」写成「青铜石质肩甲」、把「骨白弯角」写成「金色弯角」、把法杖「金色鸟首衔白色水滴石」写成「金色兽首衔白色羽饰」。**做法**：把原图按面板裁切后放大 2 倍重读一次，逐件核色（甲／角／锤／杖头／护手），拿不准就在待确认项标明"我读作 X，请核对"。
   - **改完做双向核对**：既 grep「旧错误词」确认残留为 0，也 grep「新正确词」确认已落进正文——只做前者会漏掉"该改但没匹配上"的段落（本次就漏了 2 处 `蓝银`、1 处 `金色羽翼肩饰`）。
4. **交付双文件**：`01_原剧情整理_<系列名>.md`（可直接读的干净剧情，含人设表、逐镜剧情、笑点/埋线清单、原文笔误修正表）＋ `02_AI视频提示词_分镜脚本.md`（本技能三层结构）。第一个文件是用户核对剧情的凭据，不能省。
5. **另出一份「零修改逐字转写」文件**：用户经常要拿它来对账，核对提示词是否与脚本一致。`00_脚本原文逐字转写.md`，逐行照录、不改一字，只在文件头声明分段符非原文。

## 用户说「要能直接落地执行、不要笼统」时（必做的四件事）

用户手上通常**已经有主角／NPC／场景参考图**，只是没告诉你。先问或先找，别急着用文字硬描述。

1. **先找齐参考图**：翻项目目录（含 `素材/`、`场景类/` 等子目录），按修改时间排序看最近新增的图片——用户常常刚传完就说「我有参考图」。找到后建 `refs/主角`、`refs/NPC`、`refs/场景` 三级目录。
2. **一张图里有多个人物时必须切开**：设定图常把 2 个角色拼在一张图上，`@` 引用整张会让模型混角色。切法：`lum<120` 求行／列投影、取连续 run 定位每个人物块；双人并排的实拍图再手工框切。切完生成一张**缩略图网格**一次核对全部切图是否正确（比逐张读省大量额度）。
3. **镜头必须按四要素写死**，不要写「跟拍」「推进」这种笼统词：
   `景别（人物占画面比例）｜机位角度与高度｜运动方式＋速度／距离／秒数｜落幅停在哪`
   例：「中景（腰以上），机位在角色右前方 2.5 米、平视略仰 5°，出拳瞬间 0.3 秒急推 1.5 米到近景，落幅锁定收拳侧脸」。
   - ⚠️ **这条是"要能直接落地执行"时的口径，不是铁律——当次用户的偏好优先**。同一个用户后来明确说过：**「人物占画面多少这个不用写，机位写景别和运动就行，别写太复杂」**。此时运镜压成 `景别 ＋ 运动` 两件事（如「中景，小幅环绕。」，平均 8 字），删掉画面占比、机位距离与角度、运动秒数、落幅。
   - **判断口径**：用户说"要能直接落地执行／不要笼统"→ 四要素写死；用户说"别写太复杂／给 AI 留发挥空间"→ 只写景别＋运动。**问一句比猜好，改完在交付说明里写"别往回加参数"。**
   - 同理，画面描述也有这两档：细（四段式、箭头串因果）／粗（只留谁做什么，30–60 字）。**全局锁（设定卡＋Style）负责所有细节，镜头层只负责"这一镜干什么"**——这才是三层骨架的用法。
4. **@ 引用体系**：
   - 有图 → 挂 `@角色名`，并在设定卡写死该角色的配色与配件，负面词里加「@角色 的 X 变色/缺失」保护。
   - 无图的小怪／路人／道具 → 开一张「**文字定金表**」，每个资产一行写死外观（尺寸、颜色、数量、有无武器护甲），分镜里每次出现都照抄同一段。
   - **场景图里的小怪可以直接当怪物外观引用**（如蜘蛛场景图 → `@蜘蛛挂机点` 锁蜘蛛造型）。
   - 怪物、路人不必单独出图，用「三档配色 + 统一造型模板」比逐个设计更稳。

## 分镜 ≠ 镜头：一镜一句，必须拆开（用户最常指出的问题）

源脚本通常是「分镜 01–09」这种**叙事段落**，一个分镜里会塞 3–5 个不同角色的发言。**直接把一个分镜当成一个镜头写，是必错项**——用户一定会退回。

规则：
- **每一个说话人 = 一个独立镜头**；同一人连说两句且情绪递进时，也建议拆成两镜（换机位、换景别）。
- 没有台词的动作／反应／定场也要各自成镜（撞飞、停顿沉默、点头、背影定格）。
- 每个带台词的镜头都要单独写：景别、机位角度与高度、运动方式＋速度／距离／秒数、落幅停在哪。**不要复用上一个镜头的机位描述**。
- 常用机位词库（避免重复）：横移跟随 / 过肩正反打 / 低角度缓推 / 过肩特写 / 微距 / 甩焦 / 环绕锁焦 / 固定小幅推轨 / 手持轻摇 / 仰角近景 / 背影跟拍 / 拉升定格。

## 用户说「把镜头X改一下／拆成几个镜头」时：编号重映射（必做，最容易漏）

用户常在定稿后回来说「镜头1 和 2 拆开，拆成 6 个，展示混乱状态」。**这不是改一镜，是整片编号位移**，必须当成一次全局重构来做：

1. **先算账再动手**：新镜头数 N、各自时长（有台词的按字数反算，无台词的按动作必要时长给 1.2–2.0s）→ 得出**新增时长 Δ = 拆后总长 − 拆前总长**。若用户给了上限（如「12 秒内」），就从上限往回收，别超。
   - **先判断用户要不要加时长**：如果用户没说加，**默认「拆分后保持总长不变」**（如原 1 镜 3.0s → 拆成 1.5s ＋ 1.5s）。这样**时间码一个都不用动，只有编号 +1**，改动量小一个数量级，也不会连带影响下游所有分镜。用户主动说「拆开、每镜给足」时再加时长。
2. **顺序很重要：先给后面的镜头批量重编号（+N−原镜数），再插入新镜头**。反过来做会把刚插进去的新镜头一起误伤。批量重编号用正则匹配 `\*\*镜头(\d+)（([\d.]+)-([\d.]+)s）` 并同时 +编号、+时间码，**一次跑完再核对**。
   - **⚠️ 三个必踩的坑（本技能已验证）**：
     - **① 定位串会跟着变**：拆镜脚本里用来定位「下边界」的镜头标题（如 `**镜头10（21.0-26.0s）`）在重编号之后已经变成 `**镜头11（…）`，用旧标题定位会 `IndexError`。**重编号后再写定位串，别提前写好。**
     - **② 匹配串要用「替换后」的形态**：文中形如「镜头35＋36」的复合表述，批量 +1 只会命中带「镜头」前缀的那一个，结果是「镜头36＋36」——用它**替换后**的写法去匹配才能改对，用原文匹配必 MISS。
     - **③ 不带「镜头」二字的镜号一律命中不到**，有两类，都要单列手工清单：
       - **计数表述**：`46 镜头`、`47 镜头`（版本行、设定卡、第 4/8 步标题、第 6/7 步合计、第 10 步合计各一处）
       - **表格里的裸数字镜号列**：第 6 步语速／时长核算表的首列是 `| 10 |` 这种纯数字，没有「镜头」前缀 —— **这一列最容易被整列漏改**，改完要用「表里镜号 ↔ 镜头块」双向核对一遍
   - **⚠️ 抓 MISS、别静默失败**：每一条替换都写成 `assert a in s`，**全部替换完再统一写文件**。这样任一条没匹配上会直接抛错、文件保持原样，而不是改一半留一半。
3. **⚠️ 改写某个镜头的正文时，最容易把台词一起弄丢**。本类文档的台词**常常内嵌在「粘贴正文」那一行的末尾**（例：`…肩线绷紧、眉头越皱越深。莱拉台词**（男中音…）**：离谱，太离谱了。…`），**不是独立行**；一旦整行重写正文，台词就被顺手覆盖掉了。所以：
   - 改写前后都要**从第 6 步语速表取出「有台词的镜号名单」**（那份表就是台词清单的权威口径），**逐镜在镜头块里搜关键词**做双向核对。
   - **关键词要放宽**：`台词|大喊|吐槽|自语|嘟嚷|调侃` —— 只搜「台词」会漏掉用「低声自语」「委屈嘟嚷」写法的镜头，产生误报。
   - 补回台词时**保持该分镜原有体例**（同分镜里是内嵌就内嵌、是独立行就独立行），别在同一个分镜里混两种格式。
   - 校验时若打印「命中的第一行」，注意它可能只是**标题行**（标题里常带「吐槽」二字），要打印**全部命中行**才不会误判。
4. **拆镜的分配原则**：让每个新镜头**各承担一类信息**（拆镜的根本原因就是"信息过载"）。典型分法：定场俯视 → 主体落地／聚集 → 贴地微距细节 → 角色特写＋台词 → 冲击／动作 → 反应＋台词。**不要拆成"同一构图切两半"**，那样白拆。
5. **⚠️ 必须同步的 10 处（漏一处就前后打架）**：
   ① 头部版本行（版本号 / 总时长 / 总镜数）
   ② 设定卡「总时长／镜头数」格
   ③ **各分镜段落标题的时间区间**（注意标题里的副标题文字可能和模板不一致，用正则 `^### ▍分镜(0N) · (.*)（a-bs）$` 匹配，别硬编码整行）
   ④ 第 4 步镜头层标题
   ⑤ 第 6 步语速／时长核算表（**逐行镜号 + 合计**）
   ⑥ 第 8 步生成单元清单（涉及镜头号 + 时长；若开头被拆，**G 编号也要整体偏移**）
   ⑦ 第 9 步脚本→提示词对照表
   ⑧ 第 10 步审计表（10.1 汇总／10.2 台词／10.3 画面／10.4 音效 四张表的镜号）
   ⑨ **声线锁块 B `DIALOGUE` 的对白表镜号**
   ⑩ **正文里对其他镜头的交叉引用**（如「与镜头34 构成正反打」「背景只允许出现在镜头38 与 46」「镜头39–45 属同一机位区」）——这条最隐蔽，务必用 `镜头\d+` 全文搜一遍核对。
   - **别只批量替换「第 4 步–第 11 步」这一段**：还有两个**区间外的当前编号区**会被漏掉——**声线锁块 B 的 `DIALOGUE` 表**（在第 2 步之前）和**设定卡【场景】行**（场景 → 镜次映射，同样是当前编号）。这两处必须单独跑一遍。
   - **反向陷阱：区间内也混着「旧编号说明行」**，它们**不能机械 +1**。典型如「V2 语速锚点：艾斯特 镜头35＋36 两句共 40 字」「结尾镜头42 收在空间嗡鸣上」——这些数字属于当时那一版，机械 +1 会得到一个不存在的镜号。**做法：批量跑完之后，专门回扫一遍含镜号的说明性文字，逐条判断"它是当前编号还是历史引用"，历史引用一律手工归位到当前正确值。**
6. **历史记录章节加「编号口径」声明**：老的复核记录（V2/V3 期）里是旧编号，别改数字，**在章节开头加一句「本节为 VN 期镜号，V(N+1) 起编号 +N」**，并在受影响的具体行后补一句对照（如 `镜头34（现编号 39）`）。**累计位移要写清楚**（如「V4 +4、V5 再 +1」），并明确一句「以第 4 步镜头层为唯一准绳」。乱改历史记录比留旧编号更糟。
7. **画外音 → 画面内说话**（用户爱改这个）要连带做三件事：① 给说话人**补一条文字定金资产**（写死外观）② 该镜改成**近景／特写＋需要对口型** ③ 台词原文**一字不改**，只改呈现方式。
8. **用户说「用客观一点的角度」时的口径**：意思是**去掉主观代入机位**（贴背后跟随、随主体快速前推、过肩代入），换成**旁观者机位**——机位固定在侧方 N 米外、给全／远景、镜头基本不动（或仅极慢横移），并在正文里显式写「**不贴身、不跟随、不代入**」。拆镜时正好可以一镜给"场上主体"，一镜给"环境／群像"，两镜都用固定机位，客观感更强。
9. **交付时给一张「原 N 镜内容 → 新 M 镜」映射表**，逐项列出原镜的每个画面元素落到哪个新镜，证明**零丢失**。用户最在意的就是"改了但没丢东西"。

## 时长必须用台词字数反算，不能拍脑袋

凭感觉写「90s / 9 分镜」几乎一定超。正确做法是先算再排：

1. 逐句统计台词字数，按角色定语速（字／秒）：语速快／喊＝6.0；普通对话＝5.5；沉稳／冷静＝4.5；卡顿／机械／小声委屈＝3.5。
2. 每句时长 = 字数 ÷ 语速，向上取整到 0.5s。
3. 无台词镜头按动作需要单独给 2–5s。
4. 总时长 = Σ台词时长 ＋ Σ动作镜头时长。**先算出真实总长，再报给用户**，并给出三档方案：
   - A 完整版（真实时长，台词全留）
   - B 快语速版（画面不动，只把语速拉快到 6.0–6.5 字／秒，说明会损失哪些气质，如机械卡顿感）
   - C 买量精简版（列**逐镜删减清单**：哪些镜头合并、哪些删除、哪些台词改短句，给出压缩后时长与丢失的表演点）
5. **不要为了凑一个好看的数字去压缩时间码**——那会导致每句台词只剩 1 秒画面、镜头乱切。
6. **用户一旦给出实测数据，实测优先于任何估算**。真实生成／配音出来的秒数才是准绳——例如用户说「某角色两句共 40 字实际说完约 5 秒」，那就是 **8 字／秒**，此时要**以它为锚点重估全片**（分角色分档，不要全片一刀切），旧稿按 4.5–5.5 字／秒算的一定虚长，必须出一版 V2。

### V2 时长复核：两类「拖沓」要分开查

用户说「检查一下其他镜头是否时长太拖沓了」时，别只重算台词，**无台词镜头的留白同样是重灾区**：

1. **台词类拖沓**：语速上修后，原时长明显超出「台词净时长」的镜（如 20 字却给了 4.5s）。
2. **留白类拖沓**：无台词的动作／定场镜给太长——典型症状是**镜头运动距离很短却给了很久**（「横移 2 米，全程 10 秒」＝ 每秒 0.2 米，观众在干等）。判定后同步改掉正文里的**速度数值**，否则时长与速度自相矛盾。
3. **必须留的不能压**：含升格／定格／转身等复合动作的镜（如砸板＝升格 0.5s＋定格 0.8s＋转身），以及**人设要求慢的档**（机械卡顿、委屈小声）——这些压了会毁表演。
4. **交付一张逐镜新旧对照表**（`镜 / V1 时间码 / V1 时长 / V2 时间码 / V2 时长 / 增减`），并把「判为拖沓／保持不动」分开列出原因。用户要的是可核对的账，不是一句「已优化」。
5. 重排后**全文的时间码引用都要跟着改**：分镜段落标题的区间、设定卡总时长、镜头层标题、语速核算表、时长方案表、生成单元表的时长列、待确认项——漏一处就自相矛盾。

## 中途换场景／换机位（用户常拿一张新参考图说「这场用这个」）

用户丢来一张新场景图并口述站位时，**不要只改那几句画面描述**——场景改动会牵动 8 个地方，漏一个就自相矛盾：

1. **存图入库**：把新图存成 `refs/场景/@场景_<名字>.png`，并在 @ 引用表加一行。
2. **设定卡场景行**：追加 `@新场景`（镜头区间 ＋ 一句话场景构成）。
3. **该段全部镜头的 `@引用` 行**：逐个换掉旧场景。
4. **重算机位几何**——这是重点。按用户口述的站位推导「定场／正反打／收尾」三组机位方向，再逐镜写：
   - 定场镜：从哪个方位、多高、什么俯仰角，落幅要同框哪些地标；
   - 发言镜：机位在人物哪一侧、朝哪个方向反打，**背景里出现什么**（用户说的「身后是什么」就写进背景）；
   - 收尾镜：镜头在谁身后、朝哪走，拉升定格后画面能看见哪几个区域。
5. **地标写死**：把用户点名的方位关系（如「传送通道在桥的另一端，正对六人朝向」）写成一句**不变量**，措辞一致地只出现一次。
6. **负面词**加场景一致性禁止项（地标错位、缺失、方位颠倒）。
7. **生成单元表的 `@引用`** 逐行同步；衔接技巧补一句「用同一张场景图锁住 X／Y／Z 方位」。
8. **脚本对照表／完整性审计表**加变更说明；若与原脚本冲突（如原文「身后是混乱的新手区域」被换成「身后是城内广场」），**说明如何保留原文语义**（例：广场同样处于「彻底混乱」状态），并在待确认项点出来。

### 一张参考图盖不住整个空间时：**双图拼一条连续空间**

参考图常常「角度有限」——例如只有城门这一侧的桥头，看不到桥的另一端，而剧情要求在桥的另一端发生事情。这时**不要硬用一张图**，做法是：

1. **补第二张场景图**存进 `refs/场景/`，两张图各管一端。
2. **在本段最前面写一张「空间关系图」**（ASCII 轴线图 ＋ 2–4 条不变量），把轴线写死：
   ```
   [A区] ── 门 ── ◉ 人物站位 ──── 通道 ──── [B区] ── [目标]
         ↑ 身后                                    ↑ 正前方
   ```
   再逐条写明：身后是什么、正前方是什么、**关键物件（传送门／目标物）落在哪个接缝处**、两张图各管哪一段、**色调如何统一**（两张参考图光位经常打架，例如一张夕阳一张白天日光——要明确把哪张压成另一个的色温）。
3. **每镜 `@引用` 行按需挂两张图**（只在真正需要看到那一端时才挂第二张，避免模型把 B 区画到 A 区那侧）。
4. **定场镜改用「横跨式」机位**：机位放在轴线正侧方、地面／水面之上 45° 斜俯，光轴与轴线近垂直——一镜同时收到 A 区、接缝、B 区三点，比正面机位信息量大得多。
5. **收尾镜**：机位在人物身后、目标物钉在画面正中，跟拍再拉升定格，落幅要能看见「A 区 ＋ 接缝 ＋ B 区」全部。
6. **负面词加位置类禁止项**：「B 端没有 X（画成了 Y）」「关键物件跑出接缝（悬在空中／跑到 A 端）」。
7. Markdown 排版注意：**不要把 `~~~` 代码块套在 `>` 引用块里面**（部分渲染器会崩），空间关系图直接放引用块外面更稳。

### ⚠️ 背景跳变（shot-to-shot background flip）：双图场景最易踩的雷

用户反馈「某个角色的**背景发生了跳变**」时，根因几乎总是这两条，一起排查：

1. **反打镜错挂了远端场景图**：同一机位区（如"站桥面朝城门反打"）的镜头，只该挂近端图；一旦同时挂上远端图（`@森林桥头`），模型会在两张图之间来回挑背景 → 跳变。
   **修法**：把这批镜头里的远端图**逐行摘掉**，只留近端图。
2. **用「看向 X」把 X 拽进了背景**：写「视线落在桥另一端森林里那道传送门」时，模型会试图把森林**画进背景**。
   **修法**：改成**纯视线／头部朝向**表达——「头部只做极小幅度地转向画面右后方（朝画外的桥另一端望去）」，并补一句硬约束「**画面内不出现 X、背景不做任何切换**」。

**预防写法**：在段落顶部加一条 **「背景锁定铁律」**，明确写出「哪几个镜头属同一机位区、背景一律锁定哪张图、远端场景只允许出现在哪两镜、需要看远端时一律望向画外」。这一条比在每镜里反复写"不变背景"有效得多。

## 声线锁（多人对白的全局锁，务必单独成节）

多人短剧一定要把**声线**写成独立章节 ＋ 每句台词带标注，否则配音会串味。做法：

1. **先定性别，别按外观猜**。用户给的人设图可能与口头设定相反（本次 `@莱拉` 视觉偏中性／女性化，但用户明确说是**男性**）。**用户口头说明优先于外观推断**，一旦定下就写进「性别铁律」。
2. **四维区分**，保证两两可辨：**音区（男低／男中／男高／女中）＋ 音色（浑厚／清亮／沙哑／尖细）＋ 语速（最快／慢／断断续续）＋ 气息（稳／冲／气声多／发虚打颤）**。
3. 写成**「声线锁」表格**（角色／性别／四维描述／一句话听感），放在设定卡之后，并声明「**跨镜不得变声**」。
4. **每句台词前加括号标注**，且**全文逐字一致**（例：`艾斯特台词（男低音·浑厚胸腔共鸣、节奏沉稳、句末下沉）：…`）。标注是"声线指派"，比在段落里写"语气严肃"有效得多。
5. 无台词角色也要写（如哑巴主角：「无台词，只用低沉鼻息与喉音」）；NPC／群杂也要分档（机械电子音／群体男声破音）。
6. **必须另给两块「可直接复制的纯文本」（表格只供人读，不能拿去生成）**。用户迟早会提「声线锁你要给可以直接复制的提示词我呀」——表格是给人看的，模型吃不了，所以每次都要主动附上：
   - **块 A｜`VOICE` 声线锁**：与 STYLE 块、NEG 块并列的 ```` ``` ```` 代码块，一段纯文本，逐角色写「角色（性别）：音区＋音色＋语速＋气息＋听感」，末尾附「音频硬规则」一行（无 BGM／无字幕／无旁白／只留人声＋环境动作音效）。**用法声明为「每镜都带上」**。
   - **块 B｜`DIALOGUE` 逐句对白表**：每行 `镜NN 角色（性别·声线）｜台词原文`，一个镜头一行，无 markdown 噪声。**用法声明为「生成某镜时只取该镜那一行拼在 prompt 末尾」**。
   - 两块的台词必须与原文逐字一致，**块 B 的行数要等于该版本的台词句数**（做完全片后数一遍核对，如 28 行／14 行），别漏行或多行。
   - 若同时存在完整版与精简版，**两份各自的块 B 要用各自的镜号**（精简版删掉的台词不能留在块 B 里）。

## 音频与字幕规范（先问或先定，别默认加 BGM）

短剧/买量片的音频规格差异极大，**不要默认给每个镜头配 bgm**。先确认属于哪一档，再据此写「音效」行：

- **纯对话＋纯音效**（用户最常见的要求：**无 BGM、无字幕**）：音效行里**只写环境底噪 ＋ 动作点音**两类，一个字都不许出现 `bgm／配乐／小配乐／情绪垫乐`；画面内不叠任何文字。
- 有 BGM 版：才写「配乐」类音效。

做法要点：
1. 每个镜头单列一行 `**音效**：`，内容用顿号分隔，**只有环境声与动作声**（如「打铁声、怪物撞墙声、系统紊乱杂音」）。
2. 段间**不做音乐性过渡**，改用**环境声的连续性**衔接（同一场景延续同一条底噪：工坊续打铁声、旷野续风声）。
3. 末尾镜头收在环境声（如空间嗡鸣＋风声）上，画面定格即结束。
4. **必须在设定卡或独立章节写死一条「音频规范」**（允许／禁止三层表：人声层／音效层／画面层），并同步把这些词写进负面提示词：`背景音乐，BGM，配乐，旋律，音乐可视化，歌词，字幕条，对白字幕，标题文字叠加，片尾字卡，贴纸文字`。
5. **原脚本里的「bgm／配乐／片尾字幕」怎么处理**：用户这轮说无 BGM 无字幕、上轮说别删剧本，两者会打架。做法是——按新指令移除，但**把每一处移除都列进「移除清单」表**（出处／被移除内容／说明），并在说明里给恢复建议（如片尾那行字改为**剪辑阶段另叠的图形卡**，绝不写进 AI 提示词，否则模型会把它画进画面）。
6. 交付前用正则扫一遍 `bgm|BGM|配乐|字幕|音乐`，逐行确认剩下的命中全是「新写的规范说明」而非漏改。

## 输出结构（在模板三层之上，额外加这两层）

- **生成单元清单（首尾帧衔接表）**：逐行给出 `单元 / 对应分镜 / 时长 / 首帧 / 尾帧`。分镜多于 8 段时，把需要拆分的快剪段（如「4 子镜」）单独列成 U8-1…U8-4。
- **逐段可直接复制版**：先给一次 `STYLE` 块和 `NEG` 块，再给每段一整段纯文本（本段画面 + 台词）。**不要把 STYLE 重复塞进每一段**，用户自己拼接；台词直接写在段落末尾，不加字段标签。

- 模板是纯结构骨架，**不代入任何默认风格**；不要把某次示例的风格词（如水墨、金紫光效）带入新创作。
