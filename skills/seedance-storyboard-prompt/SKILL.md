# Seedance 分镜提示词流水线

## 开场必读

1. 先读真源规范：`references/seedance-prompt-spec.md`（本 skill 只是流程索引，规范是唯一真源）。
2. **表情优先筛选**：先读 `references/expression-library.md`，从 31 条标准词条里挑最贴近的一条引用，**并当场展开为「眼部 + 嘴角 + 面部」三维度描述（全流程双写，脚本与提示词同样处理，禁止只写【词条名】裸奔，详见下方硬规则）**；**严禁自造近义词**；库内无贴合词条才标「表情【自定义：…】（待确认）」并与用户沟通。
3. **电影技巧优先查库**：`references/cinematic-techniques.md`（或同名 .json）收录 melies.co 全站 **424 条技巧**（13 类：镜头运动 86 / 构图景别 25 / 角度 19 / 灯光 41 / 构图 32 / 镜头光学 17 / 色彩胶片 19 / 时间运动 21 / 机内特效 57 / 剪辑转场 23 / 氛围天气 13 / 类型风格 27 / 病毒风格 44），每条含别名、定义、叙事功能、怎么拍、何时用/不用、近似对比、片中实例、**Prompt 模板**、示例 Prompt、常见错误。**选镜头语言/灯光/构图/风格时先查本库挑词条**，选中的把 Prompt 模板翻译/本地化进 Shot 的「镜头」「光影」字段；库内无贴合再自造，并注明。词条正文为英文原文，直接引用 Prompt 时可整段英文嵌入中文提示词。
   - **检索方式（二选一）**：① 跑脚本（推荐，输出精简）`python scripts/search.py 压迫感 --n 6`，支持中文意图词/英文关键词/`--cat` 限定分类/`--name "xxx"` 取全文/`--full` 全字段/`--intent` 列意图词；② 直接 Grep `cinematic-techniques.md`。**不要整篇 Read 这个 1.3MB 文件**。**默认输出已含「避坑」行**（自动抽出该词条的 Do not / 常见错误），引用模板前必看——少数模板段落是反例（如 Low Angle 模板写 "no dramatic upward angle"）。
   - **感觉词 → 专业词条**：先查 `references/intent-to-technique.md`（意图映射表，含情绪/场面/时间/光线/风格五类 + 组合配方），把"压迫感""燃""反转要狠"翻译成具体词条，再用上面的检索脚本取全文。

## 阶段零 · 想法优化（用户给的是粗略想法/一句话/毛坯脚本时必走）

当用户给的很粗（一句话、几句情节、无镜头语言、无光线设计），**不要直接进阶段一**，先做优化提案，等用户选定后再展开成脚本。

**5 步：**

1. **拆意图**：从原文里抽出情绪/场面/节奏/风格四类意图。用户没写的，按剧情类型**合理推断**并标注「（推断）」，不自作主张改剧情。
2. **查库选型**：每个意图 → `intent-to-technique.md` 找候选 → `search.py` 取定义与 Prompt 模板。每类给 **2–3 个候选**，不要只给一个。
3. **出提案表**（格式固定）：

   | 意图（原文/推断） | 候选技巧 | 推荐 | 理由 | 对原想法的具体改写 |
   |---|---|---|---|---|

   推荐项要写清**为什么选它、放弃了什么**（例："Dolly Zoom 比 Crash Zoom 更贴'认知崩塌'，后者偏喜剧 sting"）。
4. **给改写对照**：把用户原文和"套用技巧后"的写法并列，让他一眼看出变化。**只在镜头语言/光线/节奏层面改写，不改剧情和台词**。
5. **等确认**：用户拍板（或说"你定"）后才进阶段一展开完整脚本。

**硬约束**：一镜只用**一种主导镜头运动**；情绪靠「运动 + 角度 + 光 + 景别」组合，不靠堆词；引用模板前扫一眼该词条的「何时不用/常见错误」，少数模板段落是反例。

## 口播驱动分镜（用户给了配音/口播音频文件时，必走）

**不要凭感觉估每句口播的时长，先量化断句。** 拿到音频路径后第一步跑静音检测：

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1 "路径.mp3"
ffmpeg -hide_banner -nostats -i "路径.mp3" -af silencedetect=noise=-32dB:d=0.18 -f null - 2>&1 | grep -E "silence_(start|end)"
# 停顿太短没检出来时，放细一档：noise=-38dB:d=0.10
```

拿到每个语音段的起止秒数后：

1. **先建「音频节拍对照表」**（语音段 / 口播原文 / 起–止 / 时长），写进脚本文件——这是分镜时间轴的唯一依据，也是后面剪辑对齐用的表。
2. **字幕数校验**：`中文字数 ÷ 语音时长` 应在 **4.5–7 字/秒**。若某段算出来远超 7 字/秒，说明你**把两句话并成了一段**（漏检了中间的短停顿），回去放细阈值重测；反之若低于 3 字/秒，说明停顿被当成了语音段。
3. **切镜规则**：镜头边界优先落在**静音区间**里；用户要求「尽可能多切」时，可以在**同一语音段内部**按动作另加切点（一个语音段拆 2–3 镜），但单镜**不短于 0.5 秒**。
4. **插入镜（0.5–0.8s）**在备注里注明「可从相邻镜的同批素材里裁，不单独跑生成」，避免浪费生成额度。
5. **口播是旁白还是台词**要问清：若是画外音旁白（第一人称"当年我…"之类），**画面内人物一律不开口、不做口型**，否则口型会和旁白打架；同期声字段只写环境音与动作音效，人声由后期贴。
6. 口播本身是已录好的音频时，**成片通常无 BGM**（口播独占声场），同期声只留音效。

## 怎么调用

三种方式任选，效果一样：

1. **斜杠命令**：`/seedance-storyboard-prompt`
2. **说人话触发**：「写 Seedance 提示词」「补全分镜」「买量视频分镜」「帮我优化这个想法」「这里镜头怎么拍」「这里用什么光」
3. **连想法一起丢**（推荐，最省事）：

```
/seedance-storyboard-prompt

想法/剧情：（一句话或几句情节，越粗越好，细节我来补）
想要的感觉：（如"要压迫感""这里要燃""反转要狠" —— 不写我就按剧情推断并标注）
风格：（不写套默认 3D Q 版次世代国风）
时长/镜数：（不写默认 5s 一镜）
画幅：（不写套本片定稿 9:16 竖版）
参考图：（有图的给文件路径；没图的我先清点全部资产再问你：要不要我为每个资产出生图提示词）
```

## 两阶段流程（不跳步）

**阶段一 · 完整分镜脚本（先交付，等用户确认）**
1. 全局风格块（无指定则套默认：3D Q 版次世代国风 + PBR + 电影级游戏 CG）。
2. 资产清点建锚定表 → **【资产问询，不许跳过】**清点完先问用户两件事：①哪些资产已有图（请传文件路径）；②无图资产要不要我逐个写**生图提示词**（可直接生成资产正稿）。答复后按规范 §2.2.1 二分法定形态：有图 → 「（图片 N）作为……视觉锚定」；无图+要生图提示词 → 「（无图·文字生图）」行直接写完整生图提示词（角色=五要素全展开；场景=时段+内外景+结构材质+光源光质；元素=材质+结构+细节）；无图+不要 → 纯描述锚。**禁止无图却写「（图片 N：待补）」空引用**。后期用户补图，把该行升级为引图锚，描述保留。
3. 切分镜头：**一 Shot = 一镜 = 1 个主事件**；装不下就拆，编号顺延、时间轴接续。禁止镜内切镜。**用户给了口播/配音音频时，先按上方「口播驱动分镜」跑静音检测再切镜**，别凭感觉估时长。
4. **【查技巧库，不得凭感觉造词】**每镜先定镜头语言：跑 `python <skill>/scripts/search.py <意图词> --n 6`（或先查 `intent-to-technique.md`），从 424 条里选出本镜的运动/景别/焦段/角度/光学/特效词条，**每镜至少 1 条**；脚本里标 `技巧依据：<中文名>（<English Name>）`。库内无贴合才自造并注明。**禁整篇 Read 1.3MB 原文**。
5. 每镜：焦段 + 景别 + **景深与焦点（浅景深必须写焦点锁谁）** + 运动 + 机位数值（位置/离地高度/朝向）；镜头字段**中英并列**（如「极慢推近 slow push-in」）。
6. **【查技巧库·灯光】**每镜光照（时段+光源+方向/光位+光质+氛围）从灯光类词条选型（如 Practical Lighting / Chiaroscuro / Rim Light / Motivated Lighting），同样标「技巧依据」，并**写进该镜的「环境光照」文字里**——光线是提示词，不是给人看的说明。
7. 站位（画面空间顺序）+ 动作微表情（**表情库优先筛选，一律写「表情【词条名】——眼部描述；嘴角描述；面部描述」双写格式，禁止只写词条名**）+ 台词。
8. **自检后输出（两区制）**：可复制区（全局锁 + Shot 正文，无任何元信息，与阶段二正文逐字一致）→ 分隔线 → 说明区（节拍表/技巧依据/表情词条对照/参考图挂载/执行参数/口播对齐/备注/自检清单）。自检项：全局锁四要素齐 → 每镜有「技巧依据」（说明区）→ 每镜「环境光照」有实际文字 → 表情无裸奔词条名 → 可复制区零备注零元信息 → 交用户确认。

**阶段二 · 提示词生成（确认后）**
9. 用户补发资产图后，把对应「（无图·文字生图）」锚定行升级为「（图片 N）」引图锚（描述保留），更新锚定表。
10. 按规范 §4 公式拼装（表情在阶段一已双写，直接复用展开描述）；**开头放唯一一份实例化的「【全局锁】」**（风格四要素 + 资产锚定声明句，见规范 §9.3），其后依次排各 Shot 块（见下方硬规则）。
11. 同期声 + 全局约束校验，**逐镜核对技巧库调用痕迹**（镜头字段含英文术语/技巧依据可追溯），输出。

## 硬规则（踩过坑的）

- **【表情全流程双写，禁止【词条名】裸奔】所有交付物（阶段一分镜脚本、阶段二提示词）里，表情一律写「词条名 + 展开描述」**：`表情【极致震惊】——双眼骤然睁大瞪圆、瞳孔收缩、眉头高挑上扬；嘴唇微张、嘴角向两侧平拉发僵、下颌微垂；额肌收紧、面部肌肉僵住、血色略褪`。展开保留「眼部 + 嘴角 + 面部」三个维度，可压成一句连贯中文但三维度都要在。**任何地方出现孤零零的【词条名】都算违规**——模型不认词条名，用户也不该再手动展开一次（2026-09-20 二次纠正：旧规则允许脚本只写简称，导致脚本直接被拿去用时模型读不懂）。
- **【最高优先级】全局锁只写一次，放在整篇提示词最开头**：含风格串（题材/材质/ cinematic game CG, PBR material texture）+ 基调递进链（→ 连接 ≤5 词）+ 一句话色调 + 光线设计总述 + **资产锚定声明句**（按规范 §2.2 + §2.2.1 二分法逐条实例化：**有图引图，无图直接写生图提示词，禁止「（图片 N：待补）」空引用**——2026-09-20 用户定稿）。**严禁在每个镜头前重复写一遍全局锁**（2026-09-20 用户明确纠正）；分段生成时用户复制「开头全局锁 + 该 Shot 正文」即可。**锚定句只住全局锁，绝不写进「拍摄内容」正文**。风格表/锚定表只作查阅，**不能只给表格不给锁**。参考图清单、备注、风险提示挪到文件末尾独立小节；Shot 块内禁止插给人看的内容。
- **【禁表格 · 2026-09-20 用户投诉】提示词交付物里一律不要写 Markdown 表格**。表格会让用户在 WorkBuddy 预览面板里**选不中、复制不了内容**，用户为此明确投诉过。**Shot 块之间用 `====` 分隔线隔开，块内部只写「字段：内容」的纯文本行**；参考图挂载、参数、风险提示放文件末尾，同样用纯文本行，不用表格。
- **【交付文件优先 `.txt` 而非 `.md` · 2026-09-20】** `.md` 会被预览层渲染，用户反映复制不了。阶段一给人核对的脚本可以用 `.md`，**阶段二要复制粘贴的提示词一律 `.txt`**。
- **【阶段一同样适用】**：阶段一脚本虽然是给人看的，但只要用户可能复制其中的描述去用，就一样遵守「禁表格 + 整段可复制」。别因为「这是脚本不是提示词」就放松。
- **【交付两区制 · 最高优先级 · 2026-09-20 用户二次投诉】** 用户拿到手的**每一个交付文件**（阶段一脚本、阶段二提示词）必须物理分成两区，中间显眼分隔线：
  - **可复制区（上）**：`==== 以下为【可复制区】= 提示词本体，可整段复制 ====` 之后放【全局锁】+ 各 Shot 正文（仅「镜头/拍摄内容/同期声/时长」四字段），**一个多余的字都没有**；
  - **说明区（下）**：`———— 以下为【说明区】，给人核对用的，一律不复制进 Seedance ————` 之后集中放：音频节拍表、技巧依据对照（含避坑）、表情词条对照、参考图挂载与文件路径、执行参数（模型/画幅/生成档位建议）、口播对齐表、备注、自检清单。
  - **可复制区禁入清单（出现即违规）**：① 过程备注与修改痕迹，如`（非人角色：无表情词条，参照库内 @关羽机甲 先例）`——非人角色直接写实际视觉描述（如「双眼绿火骤然点亮、亮度渐强」），说明放说明区；② 给人的执行建议，如`建议按 3s 档生成、后期裁切`、`不够再补 5s 档`、`可从同批素材裁切`；③ 跨节引用`（见第三节）`；④ 文件名/路径引用；⑤ 技巧依据标注、表情来源说明、参考图清单；⑥ 库名引用`参照表情库`。
  - **阶段一脚本的可复制区与阶段二提示词正文逐字一致**；禁止出现「五、全局约束 + 执行参数」这种给人看的说明与提示词混排的节——执行参数里只有负面约束（如「画面内人物不开口、不做口型；纯音效，无 BGM」）可进可复制区的全局锁，其余全在说明区。
- **【正文禁元信息 · 2026-09-20 用户投诉】**「拍摄内容」等提示词正文里**禁止出现任何过程性元信息**——如「（非人角色：无表情词条，参照库内先例）」「（待确认）」「（自造，库内无贴合）」「表情库词条说明」这类给人看的备注与修改痕迹。非人角色/怪物直接写实际视觉描述（如「双眼绿火骤然点亮、亮度渐强」），不带任何解释性括号。所有元信息（技巧依据标注、表情词条名、待确认项、参考图清单、参数、风险）只允许出现在两个地方：阶段一脚本的「技巧依据」独立字段，或文件末尾用显眼分隔线（如「——以下为说明区，不复制——」）隔开的独立小节。**用户拿到的正文必须是拿来即用的纯提示词。**（被两区制规则吸收：元信息现在只允许住说明区）
- **【口播类短广告默认连交两阶段 · 2026-09-20】**15 秒以内的口播驱动广告（镜头数 ≤6），用户通常要的是**直接可复制的提示词**，不是等确认的脚本——阶段一脚本与阶段二提示词 .txt **同一轮一起交付**，脚本作核对用、提示词作使用用；不用停在「等确认」卡一轮。
