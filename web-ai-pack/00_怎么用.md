# 怎么用这个包（把规范喂给豆包 / Gemini / 任意网页 AI）

网页版 AI 装不了 WorkBuddy 技能、也跑不了本地检索脚本，所以这套规范被打包成**自包含文件**——规范、表情库（31 条）、电影技巧库（424 条）、交付模板、实战示例全部写在文件里，AI 读完就能照做。

## 二、三种喂法（按推荐度排序）

### 用法 A：上传文件（推荐，豆包 / Gemini / Kimi / 元宝都支持）

1. 把 `02_网页AI规范_完整自包含版.md` 上传给它；
2. **同时把 `06_规则卡_每次必读.txt` 一起上传**（或在输入框先粘贴它的内容）——这一步专治「AI 不按时长走、漏写表情三维度、全局锁重复」这类执行率问题；
3. 输入框里粘贴 `01_开场指令.txt` 的内容，填好「我的需求」那几行；
3. 有参考图的话，同一轮把角色图 / 场景图一起上传，并说明「图片 1 = 步惊云，图片 2 = 聂风……」（编号顺序就是它锚定用的编号）。

> Gemini 上下文大，**可以再追加上传 `03_技巧库_全量424条.md`**，冷门镜头语言它也能查到。豆包 / 其他模型上下文吃紧时不要加，167 条高频卡够用。
>
> **打斗题材**：无论哪个平台，都建议**再传一份 `05_打斗手册.txt`**（41 KB，加得下）。它管的是主规范不覆盖的东西——逐镜字段顺序、打击感五件套、环境破坏四段式、力量四阶梯、「炫酷打斗 / 强化打击感 / 动作不流畅」这类需求词改哪几个字段。不传的话，AI 写打斗会缺打击反馈、破坏不留痕迹。

### 用法 B：直接粘贴（对方不支持上传文件时）

1. 复制 `02b_网页AI规范_轻量版.md` 全文粘进去（约 9 万字，多数模型吃得下）；
2. 前面接 `01_开场指令.txt`；
3. 参考图只能以贴图形式给，编号按贴图顺序说明。

### 用法 C：分段喂（上下文实在不够）

1. 第一轮：粘贴 `01_开场指令.txt` + 规范第 0–4 节（角色、流程、字段、锚定、表情库）；
2. 第二轮：粘贴第 5 节技巧库（意图映射表 + 词条卡）；
3. 第三轮：粘贴第 6–8 节（两区制、自检、示例）+ 你的剧情需求。

## 三、几个平台的具体注意

- **Gemini（网页版 / AI Studio）**：上下文最大，建议 02 + 03 一起上传，效果最接近本地跑；可以把本文件也一起传，它会自己挑。
- **豆包**：支持上传文档与图片，建议只传 `02_网页AI规范_完整自包含版.md`；参考图另传并手动编号。
- **ChatGPT / Kimi / 元宝 / 文心**：同上，上传 02 即可；若提示文件过大，改传 `02b` 轻量版。
- **所有平台通用**：图一定要单独上传并**手动说明编号对应哪个角色**，AI 看不到你的本地路径。

## 四、它会怎么回你（预期产出）

1. 想法太粗时，先给**想法优化提案**（技巧候选 + 改写对照），等你拍板；
2. 阶段一：**完整分镜脚本**，上「可复制区」下「说明区」；
3. 中途一定会问你：**哪些资产有图、没图的要不要写生图提示词**（这是规范强制问询，别嫌烦，照答）；
4. 阶段二：**可直接整段复制的 Seedance 提示词**（全局锁 + 各 Shot），**每镜标题行带绝对时间段**（`Shot 04｜00:04.8-00:06.8（1.6 秒）`），正文只有**三个字段**（镜头 / 拍摄内容 / 同期声），说明区里是技巧依据、字数自检表、参考图挂载、执行参数；
5. **字数自检**：它必须在说明区附一张逐 Shot 字数表（全局锁 X 字 / 每镜 X 字 / 是否超限），保证「全局锁 + 任一 Shot」≤1800 字（硬上限 2000）。没给这张表就是没自检，直接让它补；
6. **时长自检**：说明区必须有「时长预算表」（Σ 各镜 = 你要的总时长 ±0.5s）和一行时长核对复述。**每镜标题行必须有绝对时间段、「拍摄内容」必须以时序段开头**（`时序 0.0-0.5s …；0.5-1.5s …；1.5-5.0s 完全静止…`）。它要是偷懒只写「时长：0-3 秒」这么一行孤零零的标签、正文里却没有时序推进，直接打回重写——那一行标签对生成模型没有任何约束力。

## 五、拿到结果后怎么验收（逐条看，前四条最容易出事）

| 看什么 | 合格标准 |
|---|---|
| 看分隔线以上 | 零备注、零括号解释、零「见第 X 节」、零文件路径，整段能直接粘进 Seedance |
| 看每镜 | 有机位数值、有景深焦点、有环境光照、表情是「【词条名】——眼部；嘴角；面部」三维度 |
| **看镜数和镜长**（最容易出事的一条） | 单镜 ≥1.5s；镜数 ≈ 总时长 ÷ 2.0（±2）——15s 就该是 6–9 镜，给你 15 镜就是切太碎，直接打回合并 |
| **看每镜的时间线** | 标题行必须写成 `Shot 04｜00:04.8-00:06.8（1.6 秒）`——绝对时间段在最前面；各镜时间段首尾相接、总和 = 你要的总时长 |
| **看每镜的时序段** | 「拍摄内容」以 `时序 0.0-0.5s …；0.5-1.5s …；1.5-5.0s 完全静止…` 开头，**秒数全是 0.5s 粒度**（没有 0.15s / 0.45s / 0.6s / 0.8s 这类）；段与段首尾相接无缝隙；动作段带「一气呵成做完即停」；末段止点是 5.0s 且写了「画面完全静止、无任何运动，持续到最后一帧 / holds still for the final frames」；主动作数没超配额 |
| **看说明区时长预算表** | Σ 各镜 = 你要的总时长 ±0.5s；≤2.4s 的短镜标了生成档位与裁切点 |
| **看有没有同构镜** | 连续 3 镜以上机位同、动作同、只换地面材质或背景物件 → 打回合并；正文里反复出现「无第四人、禁止第一人称」这类全局约束 → 打回删掉（只在全局锁写一次） |
| 打斗题材额外看 | 每处打击凑齐五件套（接触闪 / 形变 / 位移 / 反作用力 / 二次破坏）并有触点标记词；场景层预声明过可破坏性；上一镜的破坏痕迹在本镜被继承 |
| 看说明区字数表 | 「全局锁 + 最长 Shot」≤1800 字；超了就用 `04_字数自检卡.txt` 让它压 |

字数不放心时，单独把 `04_字数自检卡.txt` 连同提示词一起贴给它，它会逐段数并按规则压缩（绝不会为了省字删掉表情、机位、光照、弹窗原文）。

节拍不放心时（**镜数、镜长、秒数粒度这类算术问题最容易出错，而且 AI 自己往往查不出来**），把 `07_节拍自检卡.txt` 连同提示词一起贴给它，它会算出「镜长 − 动作完成点」反查收势是否够 0.3s，并直接给出修正稿。

**AI 不按时长出片时怎么办**（按顺序排查，前两条比时序段更常见）：
1. **先数镜数**——15 秒给 15 镜就是切太碎。平台最短档 5 秒，要求「动 0.6 秒静止 4.4 秒」模型做不到，必然铺满 5 秒。让它合并到 6–9 镜、每镜 ≥1.5s；
2. **再看时序末段有没有把静止写死到秒**——只写「保持到片段末尾」等于没说末尾是第几秒。必须是 `1.5-5.0s 画面完全静止…`（止点写清档位总长，等于顺手告诉模型这段片段一共 5 秒）；
3. **再看有没有亚秒数**——0.15s / 0.45s 这类模型读不出，改成 0.5s 粒度；
4. 再看动作段有没有「一气呵成做完即停」——只写 `0.5-2.0s 动作`，模型会把动作铺满这个窗口，而不是 2.0s 前做完；
5. 最后确认每镜时序末段写了 holds still for the final frames。
没有就先把 `06_规则卡_每次必读.txt` 再贴一遍。光靠「时长：X 秒」这行标签是无效的。

## 六、规范更新后怎么重出包

规范真源改了以后，重新生成即可（脚本会把最新规范、表情库、技巧库、示例重新拼进去）：

```bash
cd F:\AI视频制作\outputs\网页AI规范包
python _source\build_pack.py
```

想换示例，改 `_source\build_pack.py` 顶部的 `EXAMPLE` 路径；想改规范正文，编辑 `_source\主体模板.md`（占位符 `<<EXPRESSION_LIB>>` / `<<INTENT_MAP>>` / `<<TECH_INDEX>>` / `<<TECH_CARDS>>` / `<<EXAMPLE>>` 会被自动填充）。

`05_打斗手册.txt` 由脚本从真源 `F:\AI视频制作\outputs\打斗提示词参考手册_v1.md` 自动生成（顶部会自动加上使用说明、剔除本地技能路径引用）。改了打斗手册真源，重跑一次脚本即可。
